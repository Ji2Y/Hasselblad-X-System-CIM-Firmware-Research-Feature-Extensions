# 第一代 X2D PDAF 实验记录与离线处理

本文只规定研究记录字段，并说明如何在本机脱敏、分析操作者已经合法取得的文本记录。仓库不提供相机连接、日志采集、设备传输或状态读取步骤；所有工具均为离线脚本，不连接相机、不加载厂商库，也不控制镜头。

## 实验记录模板

每次观察使用本地实验编号。若需要分享，只保留以下经过人工核对的信息：

| 字段 | 建议记录 |
| --- | --- |
| 机型与固件 | 第一代 X2D 100C、4.2.0；不记录序列号或设备标识 |
| 镜头与模式 | 镜头型号、AF-S 等模式；不要记录镜头序列号 |
| 场景类别 | 纹理特征、近／远类别、目标是否固定；不记录地点或人物身份 |
| 事件顺序 | 开始、结束和状态变化的相对顺序或相对秒数；不要保留设备绝对时间 |
| 观察字段 | `cur_pos`、`peak`、`target_pos`、`conf` 等原始日志值，并注明尚未标定 |
| 结果与限制 | 原厂状态机记录、日志是否完整、可能缺帧；将实机观察、离线分析、合成测试分开标注 |

原始记录、照片、RAW、固件、个人路径、进程号、boot ID、设备序列号、USB 标识及绝对时间都留在本机私有位置。仓库只接收经过脱敏并人工检查的研究摘要或必要的文本样例。

## 本地文本脱敏

需要 Python 3.9+，不需要第三方依赖。先将已有文本记录保存在私有位置，再生成不同路径的脱敏副本：

```sh
cd x2d/CodeTests/pdaf-only-shadow
python3 -B sanitize_pdaf_records.py \
  --input /path/to/private/observation.log \
  --output /tmp/pdaf-observation-sanitized.log
```

脚本会将可识别的 epoch 时间改为从首条记录开始的相对秒数，并处理常见 PID、boot ID、序列号、MAC/IP、邮箱、临时目录和用户路径模式。它无法保证识别任意格式的个人信息；公开前必须人工检查生成文件，避免照片信息、未匹配的身份字段或无关日志被带入。

## 离线轨迹检查

对脱敏后的文本运行离线检查，输入与输出必须是不同文件：

```sh
python3 -B replay_afs.py inspect \
  --input /tmp/pdaf-observation-sanitized.log \
  --output /tmp/pdaf-observation-report.json
```

比较滤波器时，可显式提供本地 JSON 参数配置并将模式改为 `compare`。这些参数只是离线试验输入，不代表相机标定值。报告使用相对时间；所有轨迹建议均带 `control_allowed: false`，不形成镜头命令或性能保证。

## 证据边界

历史 2026-09-25 记录是两次原厂 AF-S 成功样本，不能据此推导通用阈值、普遍耗时或新算法效果。2026-10-08 状态表观察仅确认当时上下文引用的 972 × 42 取样组及约 90 × 3 的局部窗口；没有公开完整帧或新增候选的实机运行结果。记录模板和离线分析工具不会把研究候选变成可安装升级。

# X2D 像素位移离线处理源码

更新：2026-10-12。适用第一代 X2D 100C 4.2.0 的固定未压缩 16 位 RAW 布局。这是此前自有实验处理库的公开子集；没有相机控制、安装器、自动工作器、原厂库、照片或模型权重。

## 文件与职责

| 文件 | 职责 |
| --- | --- |
| native/merge.c、merge.h | 4／6 张 RAW 元数据校验、逐行原尺寸 RGB16 合成及 Linear RAW DNG 输出 |
| native/render.c、render.h | 矩阵／白平衡转换、JPEG 与小预览、有限区域读取 |
| native/vendor/six_row_kernel.h | 固定 MIT 六行内核；原作者署名保留 |
| CodeTests/test_merge.py | 本机构建与合成稀疏 RAW 夹具：拒绝异常输入、四／六帧处理和输出保护 |

输入只读且不能重复，版本／布局／序列及关键曝光元数据不匹配拒绝处理；输出文件必须不存在。成功或失败均不删除原 RAW。异常或取消可能留下部分输出，调用者不能将存在的文件视为成功。库不自动扫描照片目录，也不把未知 MakerNote 字段解释为会话身份。

默认合成输出 `11663×8749` RGB16，四张为原网格颜色拼接，六张为实验降采样；不是 Phocus/HNCS/DAC 算法。新实拍采集及 JSR 四亿 DNG 的结论见 [实拍与合成报告](../research/4.2.0/PIXEL-SHIFT-CAPTURE-RESULTS.md)。**该 C 库与 JSR 是不同处理器，不能将 JSR 的成片验收算作本库 C 合成成功。**

## 依赖与本地验证

合成库使用 POSIX C11 和数学库。渲染库另需 libjpeg-compatible API；开发输入为 libjpeg-turbo 3.1.0，未随库提供。C 文件可以作为本地库链接，不提供设备部署编排。

从仓库根目录执行：

```sh
python3 -B -m unittest discover -s x2d/pixel-shift/CodeTests -p 'test_*.py'
```

需要 Python 3.9+ 与本机 `cc`；只在临时目录构建并生成无私人信息的稀疏夹具。测试保留原输入布局，输出尺寸缩为 4×4，以检查真实读行、通道和文件路径；不是全尺寸图像质量／性能测量，也未测试相机 GPU、IBIS 或真实恢复。

历史源码曾完成 ARM64 静态构建，未取得该处理库完整全尺寸实拍成片验收。本次公开子集重新做主机合成测试；渲染模块的发布检查只确认编译，JPEG 质量及完整渲染流程未重新验收。

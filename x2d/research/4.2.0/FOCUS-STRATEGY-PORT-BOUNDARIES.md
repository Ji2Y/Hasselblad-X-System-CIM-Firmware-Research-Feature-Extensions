# 同样的相位区域数，是否足以照搬二代遮挡雷达时的对焦策略

日期：2026-10-08。目标：第一代 X2D 100C 4.2.0。对照：X2D II 100C 1.3.16.2。
证据：两份固件的 ELF 静态调用、局部数据读取和二代配置。本次没有连接相机，没有获取二代雷达遮挡前后的运行轨迹，没有部署补丁。

## 结论

即使第一代成功生成 425 个有效 PDAF 区域，相同数量仍不足以直接照搬二代整套策略。数据格式、空间映射、失焦量/位置换算、帧与镜头时序、状态机和失效回退是不同的适配条件。

另一方面，借鉴二代的相位目标位置优先控制不以“先达到 425 区域”为必要条件。一代已有相位失焦结果、位置命令和扫描回退，可以先在一代原厂数据接口上适配决策层。

## 固件对比

| 层级 | 第一代 4.2.0 | 二代 1.3.16.2 | 区域数相同后的剩余工作 |
| --- | --- | --- | --- |
| 相位统计 | Type3；有固定大小输入、打包结果和历史缓存 | 配置为 Type2/DSP V3；结果和上下文契约不同 | 适配结构、区域坐标、有效性及结果含义 |
| 镜头位置参考 | AF-S 读取当前/此前镜头位置与失焦结果 | AF-S 通过专门助手读取 Type2 对齐镜头位置 | 对齐采样时刻、镜头位置和失焦换算，不能只重排区域 |
| 单次对焦决策 | 同时具备位置直达与方向扫描分支 | 主函数包含网格峰值/ROI、标准差时间滤波及位置命令 | 适配目标选择、滤波、限位、状态及确认流程 |

## 1. 单次对焦的差异

一代 `_exec_pdaf_afs_process` 为 ELF VA `0x90128`，1872 字节；二代为 `0x1863f8`，2052 字节。体积只用于定位，不作为性能结论。

一代主函数可见 `lens_ctrl_get_focus_speed`、`lens_cmd_push_focus_scan_cmd` 和 `lens_cmd_push_focus_abs_cmd`，即原厂已经同时存在扫描与位置直达。

二代主函数可见 `alg_set_mesh_peak_info`、`alg_set_mesh_roi_info`、`aaa_stddev_by_time_filter`、镜头范围检查和 `lens_cmd_push_focus_abs_cmd`。这份主函数的直接 BL 中没有选扫描速度和提交扫描命令的调用；不能因此推断所有更上层/下层流程都不扫描。

二代在 `0x186438` 调用的局部助手从 `0x185f08` 开始：它检查算法类型，匹配时在 `0x185f24` 调用 `get_pdaf_type2_align_lens_pos`。其他分支读取当前/此前镜头位置。Type2 位置接口实际从 Type2 上下文的 `+0xaca30` 读取一个整数。

这说明决策入口需要特定的相位采样位置参考，而不是只需要一个长度为 425 的数组。移植必须核对每帧相位数据与镜头状态的对应关系，不能把任意一帧失焦值叠加到当前镜头位置。

二代的“网格结果与滤波 → 目标位置 → 位置命令”可以作为一代重写决策层的依据；尚未证明可以原样复制该函数。

## 2. 连续对焦不是仅替换单次对焦函数

一代 `_exec_pdaf_afc_process` 为 `0x90878`、1032 字节，主要调用 AFC 信息更新、时间滤波与运动信息。其 `afc_process` 通过算法有效性、分数和失焦信息判断，设置 ROI 后触发 `hybrid_af_start`。

二代 `_exec_pdaf_afc_process` 为 `0x1875d8`、1708 字节，另调用 `afc_ctrl_save_peak_info`、网格峰值/ROI、`afc_ctrl_get_status`、目标追踪可用性等。

二代新增导出 `afc_ctrl_process`（`0x1f2560`，40588 字节），一代没有同名导出。该函数可见 smart ROI、IMU/场景、镜头状态、帧号、时间滤波、预测时间与镜头命令等直接依赖。没有同名导出不表示一代完全不存在任何相近逻辑；这里说明两者不能按同名入口直接替换。

二代配置还有 `stats_frame_delay_vs_lens: 1`、`low_lattency_afc_enable: 1`、`afc_interval_time_ms: 30`。它们必须结合真实帧率和一代统计延迟验证，不能将数值直接复制当作兼容证明。

## 3. 遮住雷达不等于得到一套已经独立出来的无雷达固件

二代 AFC 配置为：

```
afc_ctrl_alg_cfg = [1, 0, 0, 1]  // PDAF、ToF 启用
fusion_enable = 1
master_algo_type = 0            // PDAF
slave_algo_type = 3             // ToF
backup_algo_type = 3            // ToF
```

同一配置里的 `enable_tof_tracking: 0` 是独立 ToF tracking 开关，不能用它证明融合关闭。

遮挡改变的是传感器收到的光/测量输入，并不等于上述软件配置被改成关闭。是否判定测量无效、何时不再采用、失效后走哪个分支，应由运行时有效标志与轨迹确认。本次没有这些运行轨迹，不能宣称已经还原“雷达被遮挡时的整套策略”。

在二代 AF-S 主函数的直接调用中没有看到 ToF/fusion 接口，这支持优先研究相位主导的 AF-S 路径；它不排除上游统计、共享上下文、混合 AF 或间接调用使用 ToF。

## 可迁移的范围与实现前提

可以研究迁移二代的控制规则，例如：选择可靠目标、估算目标镜头位置、多帧滤波与限位、优先位置移动、测量不可信时回到原厂流程。

应在一代原厂 Type3 输出上建立适配层，先验证坐标、量纲、镜头位置参考、帧同步和有效性。然后分别评估 AF-S 决策及 PDAF-only AFC 控制器。增加统计区域是可单独研究的改动，不应成为未经验证的前置条件或收益保证。

若要原样复用二代算法函数，必须提供它所要求的上下文、参数、结果格式、状态机接口、时序和全部相关依赖，并处理无 ToF 的分支。这些条件远多于“区域数量相同”，目前尚未完成。

# 第一代 X2D 增加到 425 个 PDAF 区域：固件可行性检查

日期：2026-10-08。目标第一代 X2D 100C 4.2.0；对照 X2D II 100C 1.3.16.2。
仅进行离线静态检查，没有连接、刷写、重启或控制相机。

## 结论

当前没有可以交付或宣布成功的“425 个有效相位区域”升级。

第一代 Type3 算法包含区域配置、ROI 换算和区域相关计算，支持继续研究更细的区域划分。但真实可行性还取决于原始相位数据、采样几何、相关窗口、校准、结果容量以及消费者是否接受新增区域。现有证据不足以证明只改配置便能产生 425 个有效独立结果。

二代采用 Type2/DSP V3 路径，第一代采用 Type3，不能直接复制二代配置或算法二进制。

软件可以研究如何重新组织已有测量信息；无法增加传感器上不存在的物理相位检测像素。另一方面，不能仅凭官方“294/425 区域”数字不同就断言软件区域数量必然受同样的硬件死限；它们不是物理像素数量的充分证明。

## 1. 区域划分确实属于可追查的软件层

第一代 `pdaf_type3_get_stat_cfg`、`pdaf_type3_roi`、`process_configuration`、`calculate_pdaf_stat` 处理配置、ROI、区域几何与相关计算。`process_configuration` 包含设置区域数、根据输入宽度计算相关窗口、根据可用 PDAF 行数调整纵向区域，以及越界/窗口无效检查。

因此有研究入口，但“有配置入口”不等于“任意网格都能正常工作”。其中一些字段描述子 ROI 或算法内部窗口，尚未完整映射到对外宣称的 294 个区域，不能直接把任一横纵数量当成界面点数。

## 2. 固定大小结果接口是明确的改造障碍

第一代 `libaaa.so` 的静态指令显示：

| ELF VA | 行为 |
| --- | --- |
| `0x8efec` | `pdaf_type3_statistics` 要求输入头中的大小为 `0x7d0`，即 2000 字节 |
| `0x8f0b4`、`0x8f0c0` | 从输入偏移 `0x10` 复制固定 `0x6ff`，即 1791 字节 |
| `0xd9b84` 起 | `pdaf_type3_stats_lib_get_results` 从输出偏移 `0x97` 开始，以 13 字节步长写网格结果 |
| `0xd9b2c`、`0xd9b34` | 输出 `0x6fe`、`0x6fd` 保存两个维度字节 |
| `0x8d2d4`、`0x8d2dc` | `pdaf_type3_run` 把固定 `0x666`，即 1638 字节的网格记录复制进历史缓存 |
| `0x8d2f0`、`0x8d300` | 临时数组清零大小固定 `0x1f8`，即 504 字节 |

这一特定接口的记录区为 `0x6fd - 0x97 = 1638 = 126 × 13` 字节；504 字节也对应 126 个 float 槽位。它表明生产、传输、历史和临时计算之间有固定容量关系。

**126 是这一特定打包接口的槽位容量，不是本次确认的传感器物理相位点数，也不是对官方 294 区域的重新计数。** 原厂区域如何映射、聚合或按 ROI 调度，仍须继续追查。

如果假设把 425 个结果直接塞进这个现有的 13 字节记录格式，所需载荷至少为 `151 + 425 × 13 + 2 = 5678` 字节，明显超过 1791 字节。这个假设用于说明直接扩展的容量问题，不表示原厂二代采用同一种记录格式。

所以直接改横纵区域数存在结果覆盖尾部字段或超出缓存的风险。若最终设计需要同时输出更多记录，必须同步改造生产者、消息结构、消费者、历史缓存、临时数组与遍历边界；也可研究分批/按 ROI 重算的设计，但它会引入时效性和运算量问题。

## 3. 二代 425 不能作为可直接移植的常量

对照固件 `etc/aaa/af/af_imx861.json` 明确配置：

- `pd_type : PDAF_ALG_TYPE_2`；
- `stat_cfg_type : af_pdaf_type2_load_cfg_s`；
- `PDAF_TYPE_MODE_DSP_V3`。

一代调用 `pdaf_type3_run`，二代调用 `pdaf_type2_run`，结果格式和处理链不同。二代配置中还出现 `mesh_num_x : 31`、`mesh_num_y : 15` 等内部网格参数；31×15=465，也说明不能拿任意一处内部网格数量直接等同于公开的 425 区域。

官方二代产品页确认 425 PDAF zones，但没有提供足以把一代 raw/stat ABI 转成二代 ABI 的映射。

## 4. 实现前还缺什么

1. 确认第一代各传感器模式下实际提供的原始相位采样几何、左右配对、有效范围和校准对应关系。“250×93”尚未验证。
2. 解释原厂 294 区域与 Type3 打包结果、ROI 和内部窗口之间的映射，避免把统计窗口、界面位置或插值结果混成新增相位测量。
3. 用真实相位数据在离线算法中生成候选划分，例如 25×17=425；验证每个区域实际包含足够的相位信号及相关窗口。25×17 仅为数学上的候选，不是二代布局结论。
4. 检查新结果对弱光、低纹理、混合深度和边缘区域的置信度、延迟与错误率，并确认下游对焦逻辑能消费。

将原来结果插值成 425 格、增加界面框数，不能作为“新增 425 个有效独立相位区域”的验证。划分更细可能减少每个区域参与计算的样本，数量增加不自动意味着更快或更准；该取舍需用真实数据验证。
